The problem · two real readings from September 2026

Every control room has the same unanswered question.

Something looks wrong. Is it the instrument, is it an operator doing their job, or is it the world? Today a threshold alarm fires either way and a person spends their shift telling them apart.

Bow River at Calgary · 70 → 0 → 71 m³/s in 25 mina fault
Indian Brook, Cape Breton · 0.72 → 294 m³/s overnighta flood

To the alarm these are the same event. Page on the first and you wake someone for nothing. Quarantine the second and you have silenced a flood. The feed carries no quality flag; the only thing that tells them apart today is a human.

What we built

One agent, on duty 24 hours a day, that reasons before it acts.

Blue: a model runs. Grey: settled without one. Amber: the system changing its own settings between rounds. A human appears only at the end of the path on the right.

Under the hood

Three small mechanisms do the heavy lifting.

The gate ai_decide

in: state JSON from the detector · out: probabilities, route

  • Station, rule, the reading against physical_min / plausible_max, neighbours over ±24 h, rain, site facts
  • Three typed questions: a choice over the three answers, a noul "is this physically impossible", a 5-level score for severity if real
  • Versioned decision model, so the same state gives the same answer next month
  • Settle only when the top probability clears the cut-off and agrees with the detector; a low-side breach never settles as real

The investigator ai_query

in: agent_state · out: verdict, severity, evidence[], rationale

  • Strict JSON schema; the model cannot answer in prose or skip the evidence list
  • The exact agent_state it saw is stored next to its answer
  • cited_hidden_evidence flags any rationale that leans on evidence switched off for that round, so the reasoning is checked against what the model was actually given
  • INCONCLUSIVE is a legal answer; the router then pages only if the river is already rising and a neighbour agrees

The evaluator SQL

in: scorecard per round · out: one change, with its reason

  • Scores what the system did per case: paged, quarantined, ticketed, nothing
  • Priority policy: real event quarantined → switch rain evidence on; fault missed → lower the cut-off; false page → weight gauge trust
  • Writes gold.plan_iterations; the next round reads it into session variables and recomputes route, verdicts and actions
  • Baseline R0, R1 and R2 live side by side in gold.scorecard

Nothing about this is about rivers.
